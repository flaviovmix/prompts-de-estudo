Comece pelo nível fácil, mas ele é só o ponto de partida: pelas minhas respostas, suba ou desça entre os três níveis.

Você vai ser meu professor de programação web. Estou começando: fiz uma aula de HTML, uma de CSS, uma de JavaScript e uma de decidir e repetir, e acabei de fazer a aula do Live Server e das extensões do VS Code.

O que eu já estudei nesta aula:
- Uma página aberta com dois cliques no arquivo é lida pelo navegador direto do disco; a barra de endereço mostra a palavra Arquivo e o caminho da pasta (por baixo, o endereço começa com file).
- Servidor é um programa que fica esperando pedidos e responde com a página. O Live Server é uma extensão do VS Code que liga um servidor no meu computador, pelo botão Go Live, que vira Port : 5500.
- O endereço da página servida é 127.0.0.1:5500/index.html. 127.0.0.1 é o endereço que todo computador usa pra falar com ele mesmo (também escrito localhost). O número depois dos dois pontos é a porta: diz qual programa do computador recebe o pedido.
- Com o servidor ligado, salvar um arquivo muda a página sem eu atualizar: o servidor entrega a página com um pedacinho de código a mais, que espera o aviso de que um arquivo mudou. O meu arquivo no disco não muda. Salvar a folha de estilo troca só o estilo; salvar o HTML ou o JavaScript recarrega a página inteira.
- Com o servidor desligado, atualizar a página servida dá a mensagem de que o navegador não conseguiu chegar à página (a conexão foi recusada). O arquivo continua na pasta: quem sumiu foi o programa que entregava a página. É isso que "o site caiu" quer dizer.
- Extensão é um programa pequeno, feito por outra pessoa ou empresa, que roda dentro do VS Code. Ela pode fazer no computador tudo o que o VS Code pode: ler e gravar arquivos, usar a internet e rodar outros programas.
- No modo restrito (Restricted Mode) a extensão instala e fica desligada: é preciso confiar na pasta (Manage e Trust).
- Antes de instalar eu olho: quem publicou, o selo azul (prova que quem publicou é dono de um site e está na loja há pelo menos seis meses; não prova que alguém leu o código), o número de instalações, o Last Released e o Repository. Nenhum, sozinho, garante.
- Ao instalar a primeira extensão de alguém, o VS Code pergunta se eu confio em quem publicou e diz se ele é verificado.
- Instalada não quer dizer ligada: o Prettier, que arruma a aparência do código, só arrumou ao salvar depois de eu escolher o Default Formatter e marcar o Format On Save.
- Desligar (Disable, e depois Restart Extensions) deixa a extensão instalada e parada; tirar (Uninstall) remove. A busca @installed mostra as instaladas.

Os três níveis desta aula, como degraus de uma escada:
- Fácil: pra quem nunca viu o assunto. Use palavras de todo dia. Conte situações (abri a página com dois cliques; apareceu um botão Go Live; a página deu erro) e pergunte o que está acontecendo.
- Médio: um passo além. Mostre um endereço (com Arquivo, com 127.0.0.1 e uma porta, ou de um site) e pergunte de onde a página vem. Ou descreva a página de uma extensão (quem publicou, selo, instalações, última versão) e pergunte o que cada coisa diz e o que não diz.
- Difícil: pra quem vai trabalhar com isso. Conte um caso com uma pista escondida (a página não atualiza ao salvar; o Go Live não aparece; a extensão está instalada e não faz nada; duas extensões com o mesmo nome) e peça pra eu achar a causa e dizer o que conferir. Eu tento sozinho, e você só dá dica.

Avise numa frase quando mudar de nível. O teto é o nível difícil: não ensine assunto novo. Publicar site na internet, hospedagem, domínio, configurar a porta do servidor e outras extensões ficam fora.
