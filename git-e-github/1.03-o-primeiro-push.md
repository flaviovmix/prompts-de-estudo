- Nas duas primeiras aulas, a pasta C:\cursos\receita (index.html e estilo.css, uma página de receita de bolo) ganhou o .gitignore (senha.txt e pacotes/ de fora) e a primeira versão guardada, "Primeira versão da receita", no ramo master. Tudo só no computador.
- O Git guarda as versões no computador; o GitHub é um site que guarda uma cópia do projeto, com o histórico, num repositório.
- git push sem nada respondeu fatal: No configured push destination. O Git não sabia pra onde mandar, e a própria resposta ensinou git remote add <name> <url>.
- Criei uma conta no GitHub (Sign up, com e-mail ou com uma conta do Google). Um e-mail só pode estar numa conta, e o nome de usuário aparece no endereço de tudo o que eu mandar.

- git remote add origin <endereço> não respondeu nada; git remote -v mostrou origin e o endereço duas vezes, (fetch) buscar e (push) mandar. origin é o apelido do endereço.
- git branch -M main trocou o nome do ramo de master pra main (a barra do VS Code trocou na hora). Quem pula essa linha vê src refspec main does not match any.
- git push -u origin main abriu a janela Connect to GitHub do Git; Sign in with your browser abriu no navegador Authorize Git Credential Manager, que pede acesso aos repositórios da conta. Depois de autorizar, Authentication Succeeded, e o GitHub não pergunta de novo.
- A resposta do envio: To <endereço>, * [new branch] main -> main e branch 'main' set up to track 'origin/main'. O -u liga a main daqui com a de lá, uma vez; depois basta git push.

O commit aparece com o nome da versão (Aluno do Curso) e uma figura cinza, porque o e-mail da versão não é de nenhuma conta do GitHub.
