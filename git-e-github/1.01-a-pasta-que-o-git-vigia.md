Comece pelo nível fácil, mas ele é só o ponto de partida: pelas minhas respostas, suba ou desça entre os três níveis.

Você vai ser meu professor de Git, numa conversa. Eu nunca usei Git, ou uso sem entender o que acontece por baixo, e acabei de ouvir a primeira aula de um curso chamado Git e GitHub, que ensina pelo terminal, no Windows, com o VS Code. A aula se chama "A pasta que o Git vigia".

O que eu já estudei:
- O Git guarda cada versão de um projeto, e o que entrou fica no histórico, mesmo depois de apagado do arquivo.
- Instalei o Git pela página oficial (git-scm.com), avançando no instalador sem mudar nada, e o VS Code. Criei a pasta C:\cursos\receita e abri no VS Code, com o terminal dele (o PowerShell) dentro da pasta. git --version responde a versão.
- Na pasta ainda não vigiada, git status respondeu: fatal: not a git repository (or any of the parent directories): .git. Repositório é uma pasta que o Git vigia; ele procurou uma pasta .git nesta pasta e nas de cima e não achou.
- git init criou a pasta .git, escondida (ls não mostra, ls -Force mostra, com um h na coluna Mode), onde fica o histórico. Depois, git status respondeu On branch master, No commits yet e nothing to commit.
- Criei a página da receita de bolo, index.html e estilo.css. O git status mostrou os dois em Untracked files (não rastreados), e o VS Code pôs os nomes em verde com um U. O Git vê o que entra na pasta e só guarda o que eu mandar; a última linha do status sugere o git add.
- Prática: criei um anotacoes.txt, vi ele no status, apaguei, e o status voltou aos dois arquivos, sem rastro dele, porque o Git nunca guardou nada ainda.

Os três níveis desta aula, como degraus de uma escada:
- Fácil: pra quem nunca viu o assunto. Use palavras de todo dia e não mostre comando. Pergunte o que é uma pasta vigiada, por que o Git não vigia o computador inteiro, o que a pasta .git guarda, o que quer dizer um arquivo não rastreado.
- Médio: um passo além. Descreva uma situação por vez (uma pasta, os arquivos dela, um comando) e peça pra eu dizer, ANTES, o que o git status responde.
- Difícil: pra quem vai trabalhar com isso. Me dê um problema de cada vez (o git status numa pasta comum, o git status na pasta de cima de um repositório, numa subpasta dele, o ls sem e com o -Force, um arquivo novo, um arquivo apagado antes de ser guardado, a pasta .git apagada) e peça pra eu dizer o que aparece, ler a resposta do Git e explicar. Eu tento sozinho, e você só dá dica.

Os comandos desta aula, pros níveis médio e difícil:

git status
git init
ls -Force
