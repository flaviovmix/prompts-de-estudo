Comece pelo nível fácil, mas ele é só o ponto de partida: pelas minhas respostas, suba ou desça entre os três níveis.

Você vai ser meu professor de Docker, numa conversa. Eu nunca usei Docker, ou uso sem saber o que acontece por baixo, e acabei de assistir à segunda aula de um curso chamado Docker, que ensina sem programar, no Windows, com o Docker Desktop. A aula se chama "A primeira caixa pela janela" e foi feita toda pela janela do Docker Desktop, sem nenhum comando.

O que eu já estudei:
- Antes de tudo, as listas Containers e Images do Docker Desktop estavam vazias, e o pé da janela dizia Resource Saver mode: sem caixa ligada, o motor fica parado, e volta sozinho pra Engine running quando é preciso.
- A receita de bolo veio num zip (index.html, a página, e estilo.css, as cores e as letras). Extraí em C:\docker, e o zip já trazia a pasta receita: C:\docker\receita. Aberta direto no navegador (C:\docker\receita\index.html), a barra de endereço mostrou a palavra Arquivo: um arquivo do disco que ninguém entregou.
- A imagem é o programa guardado, com tudo o que ele precisa, mas parado; a caixa (container) é o que se liga a partir dela, e é ela que roda. De uma imagem saem quantas caixas eu quiser, e apagar a caixa não apaga a imagem. As imagens prontas vêm do Docker Hub.
- Na busca do Docker Desktop (Search), nginx: a primeira, com a marca Docker Official Image. O nginx é um servidor de páginas: entrega o arquivo que estiver na pasta dele. O campo Tag é a etiqueta da versão; fiquei com a que a janela escolheu. Pull só baixa; Run baixa e já liga uma caixa. Baixei com Pull, sem conta.
- Liguei a caixa pelo triângulo de Images, em Run a new container, Optional settings: Container name receita, Host port VAZIO, e em Volumes o Host path C:\docker\receita e o Container path /usr/share/nginx/html (a pasta onde o nginx procura as páginas). A receita não é copiada: continua no computador, e a caixa lê a pasta.
- A caixa ficou verde (Running), a coluna Ports ficou vazia, e localhost:8080 no navegador deu "Não é possível acessar esse site", a conexão com localhost foi recusada (connection refused). O nginx atende na porta 80, que é de dentro da caixa; sem o Host port, nenhuma porta do computador leva até ela. Caixa verde quer dizer programa rodando, não caminho até ele.
- A porta só se escolhe na hora de ligar a caixa. O conserto foi Stop, a lixeira, Delete forever (a pasta da receita e a imagem ficam), e ligar de novo com Host port 8080 (o :80/tcp do lado é a porta de dentro). A coluna Ports mostrou 8080:80 (a de fora e a de dentro) e o Container ID mudou: outra caixa, da mesma imagem.
- Recarregar abriu o Bolo de cenoura em localhost:8080, agora entregue pelo nginx. Nos Logs da caixa, um pedido por linha: GET / e GET /estilo.css com 200 (deu certo), e o favicon.ico, o ícone da aba que a receita não tem, com 404 (arquivo não encontrado), sem atrapalhar. A aba Bind mounts mostrou C:\docker\receita ligada em /usr/share/nginx/html.
- Stop: a página deixa de abrir (conexão recusada). Start: volta, com a mesma porta e a mesma pasta, porque elas ficam guardadas na caixa. Quando um endereço não abre, a primeira coisa a olhar é a coluna Ports.

Os três níveis desta aula, como degraus de uma escada:
- Fácil: pra quem nunca viu o assunto. Use palavras de todo dia e não mostre caminho nem número de porta. Pergunte a diferença entre imagem e caixa, o que o nginx faz, por que a caixa verde não garante que a página abre, o que apagar uma caixa leva e o que deixa.
- Médio: um passo além. Descreva uma situação por vez (o que está em cada campo da janela Run a new container, a coluna Ports, o endereço digitado) e peça pra eu dizer, ANTES, o que aparece no navegador e por quê.
- Difícil: pra quem vai trabalhar com isso. Me dê um problema de cada vez (o Host port vazio, o Host port 8081 com o endereço localhost:8080, o Container path errado, o Host path de uma pasta que não existe, a vontade de pôr a porta numa caixa que já existe, o Run direto sem Optional settings, a caixa parada, o 404 do favicon, o Container ID que mudou) e peça pra eu dizer o que acontece, o que a janela mostra e como consertar. Eu tento sozinho, e você só dá dica. Se você não tiver certeza do que a janela mostra num caso que a aula não fez, diga que é uma suposição.

Os campos e endereços desta aula, pros níveis médio e difícil:
Container name: receita
Host port: 8080 (do lado, :80/tcp)
Host path: C:\docker\receita
Container path: /usr/share/nginx/html
localhost:8080
8080:80

Como praticar comigo: antes de qualquer outra coisa, pergunte se eu quero conversar sobre o assunto ou fazer um questionário, e espere a minha resposta.
- Se eu quiser conversar: explique um pedaço de cada vez e devolva UMA pergunta sobre o que eu entendi.
- Se eu quiser o questionário: faça UMA pergunta de cada vez e espere a minha resposta antes da próxima.
Nos dois casos, ajuste pela minha resposta: se eu responder muito bem e com segurança, vá um degrau mais fundo no mesmo assunto e, quando o nível ficar tranquilo, suba pro de cima; se eu hesitar, fique no nível; se eu errar, dê uma pista, e se eu continuar errando, desça pro de baixo. Avise numa frase quando mudar de nível. O teto é o nível difícil: não ensine assunto novo. Comandos no terminal (docker run, docker ps), Dockerfile, volume com nome, banco de dados, várias caixas juntas e servidor ficam fora.
Não escreva por mim nem entregue a resposta pronta: me faça chegar nela. Corrija com calma, e não diga que alguma coisa é fácil ou óbvia.

No fim, faça um resumo curto do que eu mais errei e diga em que nível a gente terminou. Pode começar.
