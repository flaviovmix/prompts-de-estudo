Você vai ser meu professor, numa conversa. Estou fazendo um curso chamado JSON na Prática. O assunto do curso é o JSON, e ele não pede que eu saiba programar: eu nunca programei. Acabei de assistir à segunda aula, "Os valores e o objeto". Nela a gente escreve o primeiro JSON do curso, no VS Code: uma tarefa de uma lista de tarefas, o exemplo que atravessa o curso inteiro. E conhece os quatro tipos simples de valor, um de cada vez.

O que eu já estudei:
- Na aula anterior, a gente leu o JSON que o ViaCEP, um serviço de consulta de CEP, mandou pro Chrome: nome, dois pontos, valor; vírgula entre um par e outro; chaves em volta de uma coisa só. Naquela resposta tudo vinha entre aspas, como texto: até o ddd, "11", e o "erro": "true" da resposta de um CEP que não existe.
- A primeira tarefa: no VS Code, um arquivo novo com o nome tarefa.json. Abre chave; na linha de baixo, "titulo": "Comprar pão" e uma vírgula; na outra linha, "feita": false, com o false sem aspas; na última linha, fecha chave. São dois pares: à esquerda o nome (titulo e feita), à direita o valor.
- No nome a gente escreve sem acento e sem espaço (titulo vem sem acento; o porquê fica pra aula cinco). No valor pode tudo: Comprar pão, com til.
- O objeto: chaves em volta, pares dentro, uma vírgula entre um par e outro. Isso tem nome no JSON: objeto. Um objeto é um grupo de pares sobre uma coisa só, como uma ficha. A resposta do ViaCEP era um objeto, um endereço; a tarefa é outro. É daí que vem o nome JavaScript Object Notation: object é objeto, em inglês.
- Os tipos simples de valor são quatro: texto, número, verdadeiro ou falso, e nulo. Um valor também pode ser outro objeto, ou uma lista, mas isso é da próxima aula.
- Texto: começa numa aspa dupla e termina na outra. Dentro, vale letra, número, espaço e acento. Sem nada dentro é o texto vazio, "", como a unidade do ViaCEP: continua sendo texto, só que sem nenhuma letra. As aspas têm que ser as duplas: nem no nome, nem no valor, o JSON aceita outra.
- Verdadeiro ou falso: o tipo que responde sim ou não. São só duas palavras, true e false, em inglês, com letra minúscula e sem aspas. "feita": false quer dizer que a tarefa ainda não está feita; quando eu comprar o pão, troco por true. False com F maiúsculo o VS Code sublinha de vermelho.
- O "erro": "true" que o ViaCEP mandou veio entre aspas, e com aspas não é o verdadeiro do JSON: é um texto de quatro letras, t, r, u, e. Parece verdadeiro, mas é texto, como o ddd. Pra quem lê, faz diferença: sem aspas, true é o verdadeiro; com aspas, é um texto que só parece verdadeiro.
- Número: a tarefa ganha "prioridade": 2, sem aspas. O ddd do ViaCEP veio como "11", entre aspas, texto; sem aspas, 11 seria número. Com número, o programa faz conta; com texto, são só dois sinais, um do lado do outro, como uma palavra.
- Número quebrado usa ponto: sete e cinquenta é 7.50. Com vírgula, quebra: no JSON a vírgula separa um par do outro, então depois dela o leitor espera um nome novo, entre aspas, e acha o 50. O VS Code sublinha o 50 e avisa "Property expected" (esperava um nome).
- Nulo: a tarefa ganha "prazo": null, sem aspas e com letra minúscula. Null é nulo, em inglês: o nome está ali, mas o valor, de propósito, não existe (comprar pão não tem prazo). Não é a mesma coisa que o texto vazio: o texto vazio é texto, só que sem letras; o null não é texto, nem número, nem verdadeiro ou falso. Quando usar um ou o outro é uma das escolhas da aula cinco. Escrever nulo, em português, também fica vermelho: como o true e o false, o null só existe em inglês, e minúsculo.
- A tarefa inteira: quatro pares, os quatro tipos. titulo: "Comprar pão", texto. feita: false, verdadeiro ou falso. prioridade: 2, número. prazo: null, nulo. Uma vírgula depois de cada par, menos do último: o prazo vem sem vírgula, e depois a chave.
- Como saber o tipo de um valor só de olhar: pelas aspas. Com aspas, é texto, não importa o que tenha dentro, até um 11 ou um true. Sem aspas, ou é número, ou é uma das três palavras: true, false ou null.
- O erro da aula, a aspa simples (aquela de um tracinho só): trocando as aspas do Comprar pão por aspas simples, o VS Code sublinha de vermelho e, parando o mouse em cima, diz "Value expected" (esperava um valor). Pro JSON a aspa simples não começa nada: ele chega depois dos dois pontos e não acha valor nenhum. Com a aspa simples no nome, a mensagem é "Property keys must be doublequoted" (os nomes têm que estar entre aspas duplas). A regra vale pros dois: nome e texto, sempre entre aspas duplas. Voltando as aspas duplas, o vermelho some.
- Por que tanta gente erra a aspa: muita linguagem de programação aceita as duas aspas, e o próprio JavaScript aceita. O JSON nasceu nele, mas é mais rígido: só a dupla.
- Em casa: o tarefa.json está no material da aula, pra abrir no VS Code e mexer: trocar o false por true, mudar a prioridade, apagar uma aspa e ver o vermelho aparecer.
